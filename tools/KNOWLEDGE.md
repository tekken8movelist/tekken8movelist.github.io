# 铁拳8 出招表 · 制作与转换知识库

面向未来跑新角色的任何 agent(Claude / Codex)。CLAUDE.md 讲流程,这里讲**约定、
陷阱与事故教训**。除非有意改设计,违反本文即是 bug。

## 1. 源 HTML 记法规范(手写基础 HTML 时必须遵守)

解析器(tools/pipeline.py)按以下约定断词;写错的记法会静默回退成文字或产生矮行。

- **回中必须大写 `N`**(`u/f, N, 4`)。小写 `n` 不在词表,整格作废。
  ▸ 事故:洛「升龙炮」写成 `u/f,n,4`,图形模式退化为 9px 小字,行高 25px,
  右栏整列错位 13px。
- **按住 = 方向大写**:`~F`、`B+1`、`D/F+1`、`U/B`。`f,f` 前冲写小写,
  匹配帧数据时管线自动升为 wavu 的 `f,F+`。
- **逗号三义**由上下文决定:方阵之间 = 接续(渲染 `›`);方向之间 = 连按(箭头
  相邻无分隔);`,N,` 中的回中会在帧匹配时剥离。
- **括号三义**:`(或 …)` = 备选,内部会被继续图形化;`(+53)` = 伤害标注,保留
  文字;含其他中文 = 条件注记,整段保留文字,但**帧匹配时视作接续逗号**
  (`f+2 (命中时) 1+2` → `f+2,1+2`)。
- **斜杠**:`d/f` 是方向;带空格的 ` / ` 是并列备选(帧数取第一个)。
- **状态/条件前缀写中文**,必须收录进该角色 config 的 `states`(供胶囊分词)和
  `prefix`(供帧匹配)。新词不收录 = 胶囊断错 + 帧 MISS。
- **杂散字母/数字守卫**:格内出现 BnB、H.2、i11、+5 之类,整格回退文字——这是
  特性不是 bug,别想着"修好它",标签格就该是文字。
- **十连放全宽区**(一条一行);窄表里超过 6 个方阵会自动回退文字。
- **列序统一**:打击技 `招式|指令|发生|伤害|判定`;投技 `招式|指令|发生|方向|
  伤害|挣脱`——**挣脱列是投技表的核心信息,不许省**(洛初版丢了,返工)。
- 连招表头带附注 `(T!=回旋 · ~F=按住前 · →=下一招)`;页首图例要解释该角色
  专属架势缩写(如 龙构=DSS)。

## 2. Wavu 抓取规范

- 必须真实浏览器(Anubis 反爬),加载后等 3~4 秒。
- **完整指令在 `.movedata` 卡片的 `id` 里**(`Law-df+2,3`),`.movedata-input`
  的 textContent 对连段只有尾段(前缀被洗白成独立节点),别用。
- **不要直接拼 `textContent` 读取多段字段**:Wavu 会把伤害、判定、发生帧拆成
  lead/tail 节点;节点边界本身不保证含逗号。逐个读取
  `.movedata-damageLead` / `.movedata-damage`(判定与发生帧同理),清理零宽字符,
  tail 无前导分隔符时主动补逗号。抓取后把三位以上的伤害 token 当硬错误拦截;
  `1523`、`3538` 这类通常是 `15,23`、`35,38` 被错误黏合。
- 发生帧取 `.movedata-startup`;清理零宽字符 `/[​‌‍﻿]/g`;
  结果超长必须存 window 变量分片输出(直接返回会被截断)。
- 存档格式 `input|startup` 每行,写入 `tools/wavu_{char}.txt`。
- **键名统一下划线式**:`Left_Throw`、`(Back_to_wall).`、`(Airborne).`,
  不要空格式(洛初版用空格式,与其他角色不一致,已返工)。查找端有小写兜底,
  但键格式仍应统一。
- `wavu_{char}.txt` 只保存指令和发生帧,**不会保存投技挣脱键**。方向/挣脱必须从
  Wavu 招式卡片的 notes 核对(`Throw break 1/2/1+2`、`Unbreakable`),不能从
  按键外观猜;通用正面投通常为 `1或2`,但角色指令投必须逐条确认。
- 说明卡片(含 "Input…Startup…" 长文)和超长行要过滤(`len<60`)。

## 3. 帧匹配约定(candidates/lookup)

- **发生帧 = 首击冲击帧**:连段串在第一个按键后的逗号处截断再查
  (`d/f+2,3` 查 `df+2` 的 i14)。架势派生行(`龙构中 f+1`)查派生招自身
  (`DSS.f+1`),其接续帧(带前导逗号的 `,i22`)取首 token 显示。
- **空值穿透**:候选命中但值为空时必须继续尝试后续候选(found_empty 模式),
  全部为空/未命中才显示 `—`。
  ▸ 事故:洛「空翻虚招 u/b+3,4」首击截断得 `ub+3`(空,移动技)即返回 —,
  其实完整串 `ub+3,4|i15` 有值。
- 改空值穿透后必须审计**所有**渲染行,不能只修最初报告的招式。洛的同一次修复
  还让 `1+2+3+4,1+2*,2` 从空的蓄气前缀继续命中完整串 `i14`;因此最终真 `—`
  从预估 10 处变成 9 处。回归测试应逐行比较 `lookup()` 结果,并分别锁定
  `有帧 / 候选全空 / 完全未命中` 三种返回语义。
- 兜底链(按序):`ws+1+2↔ws1+2`、`f,F+ → f+`、`FC.↔hFC.`、首字母大写方向
  转小写(`B+1→b+1`)、`,n,` 剥离、`H.` 前缀剥离(热能强化串首击=原型串首击)。
- **中文条件词后截断**:`qcf+1 命中时 F` 匹配时只取 `qcf+1`。
- **序列前缀映射技巧**:找不到独立条目的架势,可把前缀映射成按键序列——
  卍旋踢中→`db+3,3,3,3,3,`、刈足中→`db+4,`、精准闪避成功后→`b+3,P,`、
  热能+凤凰中→`H.PHX.`(中文词间的 `+` 先删)。
- **当身/防反/架势进入/挑衅显示 `—` 是正确行为**;方向列为「防反」的行直接跳过
  匹配。迎击强化型映射 `CH.` 前缀(刹那驱中迎击时→`CH.SET.`)。
- 跑完必看 MISS 清单:真缺(当身/架势)放行,可修的(前缀缺映射、写法偏差)
  逐条处理。名字对得上才算修对——去 Wavu 卡片核 `movedata-name`
  (刈足·白露 ↔ "Kariashi Hakuro")。

## 4. 布局与渲染陷阱

- **inline-flex 基线陷阱**:`.tk-in` 的基线取决于首个子元素(方阵=首格数字
  基线,箭头=盒底边),同表混排会产生 ±2px 行高漂移,双栏累计错位。
  已在管线 CSS 固化:`td.cmd .tk-in{…;vertical-align:middle}`,别删。
- **双栏区(cols2 / 2列 lt)行高必须统一**,否则左右错位。数据行基准 38px;
  某区块需要更大行距时(如洛的龙构区 48px)**必须整区统一**,不能只有个别行高。
- 主出招表应沿用基准角色的**两张独立表格**并均分数据行。不要为强制同步行高改成
  单张 10 列表:洛曾因此让长指令跨过中线,并因 `min-width` 产生横向滚动。可靠做法是
  去掉表内方向分组标题、左右均分、固定同一行高、指令 `nowrap`,中间保留明确 gap。
- 折行是错位主因:长括号注记移出指令列、或减列宽压力;攻略页(tipsPage)的
  说明列允许折行(左右无需 1:1 对齐)。
- 固定行高不代表没有横向溢出。长伤害串(洛「天翔龙」
  `24,4,5,5,5,7 (50)`)曾侵入判定列;窄 `lt` 需要给伤害列足够宽度,并用文本边界
  与下一格起点做几何检查,不能只断言 CSS 里存在 `height:38px`。
- **回退格必须是裸文本**,不要包 `<span class="tk-in"><span class="tk-txt">`
  ——包裹后 gfx 模式字号变小、行高塌陷(升龙炮事故的另一半根因)。
  标签类起手格(「BnB 替代」「低段格挡 T!」)保持裸文本。
- 3+ 列的架势 lt 一律重排 2×2;奇数格最后一格独占整行。
- **先按 Wavu section 分区,再判断行属性**:属于架势 section 的招式(包括该架势
  内的投技)必须留在对应架势表;只有字面投技 section 才进入页首投技表。先按
  `is_throw` 抽行会破坏来源语义,并让架势攻略与招式脱节。
- Wavu 十连技常用同一串的渐进前缀逐行记录。页面只显示最长叶节点,避免重复九行,
  但生成 HTML 必须用 `data-covered-record-ids` 保留所有源记录覆盖,测试按覆盖 ID
  而不是可见行数做完整性断言。
- 主题合并结构:夜间覆盖块整体前缀 `html.dark`,`--tk-acc` 用页面自己的
  `--acc` 色;浅色走组件 `.light` 变量(墨色、关辉光)。

## 5. 校验清单(每个角色收尾必跑)

1. **行高探针**(headless `--dump-dom --virtual-time-budget=3000` + 注入):
   ```js
   // 每个 .cols2 与 movelist lt 的数据行高集合应各自只有一个值
   document.querySelectorAll('.cols2').forEach(c =>
     c.querySelectorAll(':scope > table').forEach(t =>
       console.log([...new Set([...t.querySelectorAll('tr')].slice(1)
         .map(r => Math.round(r.getBoundingClientRect().height)))])));
   ```
   页面有 `body{zoom:1.25}`,所以 38px CSS 行高在 `getBoundingClientRect()` 中是
   47.5px;应比较同区行高集合和缩放后的预期值,不要硬断言 DOM 高度为 38。
2. `<td class="fr">—</td>` 清点:剩余应全部能说出"为什么是 —"。
3. 杂散字母审计:`<span class="tk-txt">[^<]*[A-Za-z]` 的命中逐个确认是
   有意保留(字面括号/徽标/标签格)。
4. 截图矩阵:夜间/浅色 × 按键图/无数字/文字(切换用注入 click 的副本验证)。
   每种状态同时断言:容器/表格 `scrollWidth === clientWidth`,单元格内容边界不越过
   下一列起点,左右表实际 gap 大于 0。截图肉眼正常不等于没有 1~10px 重叠。
5. 幂等:重跑 `pipeline.py {char}` 应输出 already processed。

## 6. 审计自身的坑

- **正则要锚定整格**,子串会误伤:按 `空翻虚招` 搜会先撞上
  `左右拳转空翻虚招`,得出"帧错了"的假结论。用
  `<td class="name">空翻虚招</td>` 级别的锚点。
- 同名招式也会重复(洛有两个「云门」)。测试不能用跨行 `.*?` 从第一个名字一直吃到
  第二个指令;先按 `<tr>.*?</tr>` 切行,再同时匹配精确招式名和 `cmd-txt`。
- 当前管线是**一遍式转换器**:检测到 `tk-notation` 就直接跳过,不会从干净源重建已
  签入页面。对处理后 HTML 的手工修复必须有结构/数据回归测试;更理想的是保留未处理
  源 HTML,或把后处理写成可重复 transform,否则 `already processed` 只证明文件没变,
  不证明产物可再生。
- 连招页的占位内容不一定含 `here`;`Combo when ...`、`Combo Off-axis ...` 也会伪装成
  路线。结构化抓取后应过滤任何以 `Combo` 开头的 route,并在页面上明确显示实际
  保留下来的来源路线数量;没有有效路线时宁可显示来源缺失说明,也不要补写打法。
- 连招 section 名可能非连续重复。渲染时可以重复标题,但不能按标题全局归并，否则会
  把后段路线提前；DOM 测试应逐行对比快照中的起手与路线顺序。
- Wavu 的 `<sup>` 注记必须在结构化快照里保留词边界，例如 `f,n,df+2 (HARD)`、
  `df+2 (on lower hit)`。禁止把注记直接粘到指令末尾，并用负例 validator 锁定。
- 几何探针计算可见内容边界时必须排除 `.sr-only` 和 `aria-hidden` 节点；裁剪后的无障碍
  文本仍可能扩张 `Range.getBoundingClientRect()`,造成并不存在的跨格假阳性。
- Season 2 四角色以 `tools/source/` 的三份 JSON 快照为输入,由
  `tools/build_season2.py` 完整重建。修改后用 `pwsh -File tools\validate_season2.ps1`
  单一入口验证源记录 ID 覆盖、明确的 section→页面分区、DOM 结构、
  第二次构建字节不变,以及桌面/响应式共 40 状态的浏览器几何门禁;
  这比对生成后 HTML 做手工补丁更可审计。
- `<title>` 探针输出前先想编码;PowerShell 管道中文一律
  `sys.stdout.reconfigure(encoding='utf-8')`。
- 脚本被 import 时不要包 stdout(TextIOWrapper 被 GC 会关掉底层流,
  guard 在 `if __name__ == "__main__"` 里)。

## 7. 批量制作 36 角色的教训(2026-07 全员补齐)

### 抓取管线(取代 §2 的单页手工流程)

- 同源批量:任一 wavu 页过 Anubis 后,同源 `fetch('/t/X_movelist')` +
  `DOMParser` 可抓任意页,无需逐页导航。每角色 2 次 fetch,间隔 ≥1.2s。
- 数据出口只有剪贴板可靠:localhost POST 被 Chrome 本地网络访问策略拦,
  第二次自动下载被多文件下载权限拦;注入按钮 + computer 工具真实点击 →
  `navigator.clipboard.writeText`(有用户激活)→ `Get-Clipboard` 落盘。
- **不要导航工作标签页**——window 上的提取器和已抓数据会全部丢失;每批抓完立即落盘。
- 提取器存档:scratchpad `tk8_injector.js`(会话目录,重要更新同步进去)。
- **wavu 3+ 段派生卡的 lead 本身就是黏连的**(`1210`=12,10,DOM 无分隔):
  damage/target 必须由父链重建(displayed_input 以 `,` 开头 → 父指令 =
  command 去掉尾段;逐级累加)。两位数黏连不会触发三位数报警,是隐性错误。
- section = 最近的 **h2 或 h3**(投技子分区 Regular/Command/Ground/Air Throws、
  DMD 等是 h3)。
- 十连技标题有 `10 Strings`/`10 strings`/`10 String`/`10 Hit Combo` 四种,
  partition 与提取都要同时匹配 "10 string" 和 "10 hit"。
- 部分页面十连技是 wikitable 而非渐进卡片:按 anna 形态合成渐进记录
  (逐击累计 damage/target,叶节点命名 "10 Hit Combo")。
- 空 id 卡(`Paul-`)与 `Generic-` 前缀卡是版面杂物:command 取 id 去前缀,
  空 command 的卡直接剔除。
- 连招页 textOf 必须剥 `https?://\S+`(视频 demo 链接会把裸 URL 混进路线文本,
  600px 不可断 literal 撑爆窄屏)。
- 同 id 多卡允许 name 不同(`1st Hit`/`(2)`/蓄力档);快照统一为首个非编号名,
  测试锁 name/command 每 id 唯一。

### 布局新机制

- `tk-cram`/`tk-cram2` 压缩级:按**渲染宽度权重**分档(方阵×1 + 箭头/N×0.5
  + 胶囊×2,实测 11px 基准下 px ≈ 43×weight):cram = 方阵 ≥5 或 weight ≥4.8
  (投技 4.0),cram2 = 方阵 ≥6 或 weight ≥5.8;>6 方阵窄表仍回退文字,
  白名单在测试 `EXPECTED_GFX_FALLBACKS`(bryan 嘲讽十连 5 行、king MMD6)。
  字号基准:表格指令 11px(对齐小羽页标准),move-table cram 9px / cram2 7.1px,
  throw-table cram 8.3px / cram2 6.4px,十连技表 cram 9.3px / cram2 8.3px
  (十连技表原本豁免压缩,11px 化后最长串会溢出,故补同档规则);
  指令列宽 move-table 37% / throw-table 34%(容 `df+1+3:qcf+2` 类一段内多变体)。
- 固定行高内允许 dmg/rng/fr/name 列换行(`overflow-wrap:anywhere`),
  注意这类规则必须 ≥ `section:not(.tipsPage) tr[data-record-id] td` 的特异性,
  否则被 nowrap 压住(fr 列曾因此失效)。
- 发生帧显示截断 `(` 后的蓄力变体(完整值在 title);十连技表行高可变,

- 连招 token(`.combo-token`)与其内部 `.tk-in` 都要 `flex-wrap:wrap`,
  且 token 须 `min-width:0`(flex 默认 min-width:auto 会阻止收缩,
  超长起手如 jack `db+3,4,3,4,3` 曾因此溢出起手列),防无空格超长路线撑宽画布。

  `Throw cannot be broken` 都要识别;确无注记显示 `—`(title 说明),

## 13. 三语站点的教训（2026-07-26 简体/繁體/英文）

### 验收标准要先立，再动手

语系重构的第一步是把简体页的 SHA256 全存下来，重构完必须**逐字节一致**。
36 页归零之后才敢往上加东西。没有这个锚点，「顺手改了个空格」会淹没在
100k 行的 diff 里，而那 41 个 URL 持有现有排名。

### 门禁的字母表自己要先立得住

「繁體页不得含简体专用字」听着显然，实现了两版都误杀：

1. 「转换器会改的字」→ 误杀 `香格里拉` 的 `里`、`征服者` 的 `征`、`背后` 的 `后`。
   简体把多个繁體字并成一个，而那个字在另一个义项上**本身就是繁體字**。
   OpenCC 已经编码了这件事：`STCharacters` 把字本身列进候选，恰好等价于「它也是繁體字」。
2. 加了自身候选判定后仍误杀 `峰`、`秘`——第三段 `TWVariants` 把 `峯→峰`、`祕→秘`
   转了回来。所以还要加一条：整条链真的会改它。

两条合起来，全语料才报 0。**门禁误杀比漏杀更贵**，因为它会逼着人去「修」正确的输出。

### 中文的单字在英文里会变成一堵墙

判定列在中文是 `上上中`（3 字），英文是 `High/High/Mid`。到七段连拳就是
`High/High/High/High/High/High/High`——四行，撑爆固定行高；十连技十七段
直接把 374px 的表撑到 593px。**凡是「一个字符一段」的中文列，翻成英文前先算最长的那条。**
现在的规则：≤3 段拼全称，>3 段用缩写，全称留 title。

### 排版缺陷只有浏览器能告诉你

英文页的五个缺陷（投技指令列溢出、Side/Break 溢出、判定撑行、十连技撑表、
手机端 name 两行溢出 2px）**没有一个是读 CSS 能发现的**，全部来自把几何门禁
扩到新语系。其中两个还各走了一次弯路，原因相同——**靠推断而不是量**：

- 手机布局本来就把 `td.name` 提到 13px，我以为它沿用桌面的 9.5px，
  加了条「恢复可读字号」的规则反而把它压回 10.5px，行高从 59 掉到 48。
- `html.loc-en` 的特异性压过了释放固定行高的那条规则；我把整块删掉时，
  连必需的 `height: auto` 一起删了。

结论：**改一条 CSS 之前，先在目标断点上量出当前计算值。** 三次 probe 脚本
比六次猜测快。

### 规格也会错，实测说了算

规格给的英文投技列宽把指令列从 34% 压到 28%——而规格自己在主表那节写着
「指令保持 37%，不要为英文重调」。28% 实测溢出 6px。按规则而不是按数字走。

## 14. 管线页出英文的教训（2026-07-27）

### 「英文缺着」被当成一个前提，其实是两个

上一轮把繁體和英文一起记成「等迁移」。繁體其实不用等——它是简体语料过转换器，
而这 5 页自己就是语料。英文确实要等 Wavu 的英文名，但那只是**一次抓取**，
不是整套迁移。把「缺」拆成「缺什么」，一半当场就能做。

### 别为几行去改共享的接合器

`pipeline.candidates()` 在首个汉字处截断，所以页面写 `d/f+3 命中时 1`、
Wavu 写 `df+3,1` 时接不上。这样的行只有 15 条。改 `candidates` 会动到简体页
帧数据依赖的那条路径，为 15 行冒这个险不值——写进 `legacy_en.MOVE_NAMES`，
逐条注明失败原因，反而可核对。

### 判定列：读字，不要读标记

简体页一段一个 span、不加分隔。中文单字连排读得通，英文变 `MidThrow`。
更麻烦的是切分不稳定：同一个 `上上中` 有时 3 个 span 有时 2 个，同一个
`中中` 有时是一个 span 两个字。所以要**把 span 里的字拼起来重新分词**，
而不是按 span 数量当段数。还得认页面自己的简写：`中×5`、`(地)`、`!`、`(投)`——
漏一个，那格就整格回退到短语表，于是多个 span 各自翻译后又粘在一起
（`HighHighSpecial`）。转成 Wavu 记号后交给生成器的 `render_target()`，
≤3 段拼全称、>3 段用缩写这套规则才会和另外 36 页一致。

### 来源标注不要逐行做视觉区分

同一件事退了两版：`ref` 角标 → 斜体 → 什么都不做。角标在屏幕上什么都没解释，
复制出来是 `Mid Kickref`；换成斜体后用户的反应是「这行长得不一样，修掉」。
症结不在选哪种标记：**一张表里五分之一的行长得与众不同，读起来像是坏了**，
而这些行并没有任何问题，只是名字的来源不同。来源是页面级的事实，就放在
页面级的位置——图例一行 + 页脚一句 + 每条名字的 `title`。span 保留（承载
`title`，也是门禁计数的锚点），但不给视觉差异。

顺带一个真坑：中途把 `.refname` 写进了 `season2_page.css`——那是生成器专属的，
5 个管线页不加载，于是那 5 页的斜体整个失效，而图例那行说明照常出现，
指着一堆看不出区别的名字。两套页面共用的规则只能放 `legend_card.css` /
`header_card.css` 这类两家都读的文件。

### 让「干净」成为构建条件，而不是事后扫描

`legacy_en.PHRASES` 缺任何一条就构建失败并打印原文。`docs/en/` 没有中文
不是扫出来的结论，是**建不出来**的结果。上一轮的教训是「放行槽位就是文案的
藏身处」，这一轮把它推到底：没有槽位，也没有默认值。

### 抓取的输出通道会截断

Wavu 抓取经浏览器返回，约 1200 字符就截断，而截断标记出现的位置和请求的
切片长度对不上——`slice(0,1100)` 也会截。用 700 字符切片、逐片核对首尾是否
接续（前一片结尾 + 后一片开头要拼成完整的一行）。另外招式名可能是
`<ul><li>` 多名列表（同一指令在不同条件下有不同官方名），`textContent`
会把它们拼成 `Windup Windup Counter`，要按 `li` 取并用 ` / ` 连。

## 15. 2026-11 数据刷新的教训（鲍勃/小罗杰上线 + 36 角色重抓）

### 抽取器要签入，不要只活在 scratchpad

7 月的注入脚本只存在于会话 scratchpad，四个月后已无从复现。现在两半都在仓库：
`tools/wavu_extract.js`（浏览器）+ `tools/wavu_snapshot.py`（离线）。新抽取器先用
`--compare` 对 7 月快照逐字段复现，差异只剩 Wavu 自己后来的编辑，才拿去抓新角色。

### 十连技表格合成：表头行不是一击，一张表可以装两条链

7 月那版的表格合成在线上留了五处错，门禁全绿：
- **保罗 / 克劳迪奥**：表头首格是空的（`['', 'Level', 'Damage', …]`），被当成第一击——
  ID 变成 `Paul-,1,2,…`，伤害 `Damage,5,12,…`，判定里的 `Level` 渲染成「下」，
  按键图多出一个空方阵。
- **金**：一张表里有「10 Hit Combo 1」「10 Hit Combo 2」两段，被接成一条 20 击。
- **恶魔仁 / 沙欣**：`1+4,,1`、`3+4,` 这类双逗号 / 尾逗号 ID。
现在 `ten_string_chains()`：单格行 = 链标题（开新链），全 `<th>` 行 = 表头，其余才是击。
**表头行判定看 tag 不看文字**——保罗那张的表头首格是空串。

门禁没抓到的原因：伤害列的「三位数黏连」报警只看数字，`Damage` 不是数字；
链长没有上限断言。看线上页面才发现。

### 刷新老角色的完整流程（2026-11-19 固化）
1. 浏览器：注入 `tools/wavu_extract.js`，`TK8.grab(page)` 全部角色 + `TK8.grabTens(page)`
   十连技表，两次 `TK8.button(...)` 走剪贴板落盘（RAW.json / TENS.json）。
2. `python tools/wavu_snapshot.py RAW.json --tables TENS.json Page=key ...`（已有快照的
   角色只给 `Page=key`，名字沿用快照）。
3. `python tools/carry_translations.py --all --write`：承接旧中文名、十连技按位次命名、
   删除消失的 ID，列出 MISSING——这些手工写进 `{key}_zh.json`，再跑到 0 为止。
4. `check_zh.py` / `move_name_en.py --check`，再用门禁报出的新期望值改登记表
   （分区、计数、发生帧覆盖、聚合伤害、described 名数——一律从构建结果推导）。
5. `validate_season2.ps1` 全绿后提交、推送、`indexnow_submit.py`。

### 刷新老角色时 ID 会漂移，翻译要「按规范化指令」承接

`FC.1→hFC.1`、`D+4→d+4`、`df4→df+4`、`H.RFS.d+4,3→RFS.d+4,H.3`——Wavu 改写法，
ID 跟着变，旧翻译按 ID 查不到。按规范化指令（大小写、`FC./hFC.`、多余逗号）承接旧名；
十连技一律按「第几击」重新命名（克劳迪奥的旧名因表头 bug 整体错位一格，不能承接）。

### 其他坑
- `Generic-` 卡（共用的热能爆发 / 蓄气）和丢了角色前缀的卡（史蒂夫 `EXD.1+2`）要保留，
  7 月快照就是这么存的；只丢弃别的角色的卡和空 ID 的图例卡。
- `<sup>HARD</sup>` 在 textContent 里会黏成 `df+2HARD`，构建器会拒收。
  `unglue_annotations()` 按 7 月的格式恢复（`(HARD)` / `(Close range)` / `(Backturned)` /
  ` (on lower hit)` / ` With heat`），`raw` 字段保持原样。
- 连招页长出了 h4 小标题：h2/h3 是分区，h4 并入上一个分区（否则一行标签变成整页分区）。
- Wavu 自己的笔误照抄不改：小罗杰 `RS.1+21+2`（连招页源码就是这样）。但连招页用 `RS`、
  招式表用 `ROC` 指同一架势，这属于别名，进 `COMBO_STANCE_ALIASES`。
- 发生帧覆盖率下降不一定是 bug：一八、艾迪的侧投与背投，维克多 `3+4`，在 Wavu 上
  现在就是空的。规则不变——不补未经来源的值。

### 搜索引擎
- 站点早已用 meta 验证过 Google Search Console 与 Bing Webmaster。Google 不接
  IndexNow、2023 年起也停了 sitemap ping，新页只能靠 Search Console 的 sitemap 与
  「请求编入索引」（每日配额约 10 条）。Bing / Yandex / Naver / Seznam 用
  `tools/indexnow_submit.py`（密钥文件在 `docs/` 根目录，发布后再提交，202 = 已受理）。
- Search Console 的 sitemap 状态长期显示「无法抓取」，但线上 sitemap 合法（200、
  `application/xml`、robots.txt 已声明），且索引报告里有 62 页已编入——这是 GSC 的
  显示问题，不是站点缺陷，不要为它改 sitemap 格式。

### 用 Search Console 的数据做决定（2026-11-19 夜间优化）
- **流量几乎全在英文页**：近三个月 1.02K 点击 / 40.7K 展示，`/en/` 主页 275 点击，
  `/en/king` 9,093 展示但 CTR 2.2%，`/en/jack` 3,090 展示 CTR 0.5%。英文页的标题与描述
  是收益最大的地方；中文页展示量小，GSC 里有 8 个简体角色页「已抓取 - 尚未编入索引」。
- **查询写的是 "move list" 两个词**（"tekken 8 move list" 537 展示，"movelist" 174），
  于是标题尾巴改成 Move List；站名 `TEKKEN 8 Movelist` 作为名字保留不动。
  繁體用户也搜「招式表」（鐵拳8招式表ps5），繁體标题写 出招表・招式表。
- **Bing 的「描述太短」阈值约 100 字符**：被标的 12 页全在 88–98（两个中文主页、
  金/熊/雷欧/熊猫/雷文/蕾娜 这些短名角色），它建议 150–160。描述改为
  `page_description_for()` 按本页实有内容组合（招式数、架势名、十连技、连招条数），
  超长时按固定顺序删部分；门禁 `test_meta_descriptions_are_long_enough_and_distinct`
  卡 100–160 且同语系不重复。旧模板还写着「确反数据」，生成器页并没有确反列——
  描述只能写页面真有的东西。

### 去掉渲染阻塞会改变 LCP 元素
主页 Google Fonts 改成 preload 非阻塞后，FCP 2.3s→1.0s，LCP 却从 2.3s 变成 6.4s、性能分
95→77：字体不再挡住首屏，LCP 就落到了第一张卡片头像上，而它是 `loading="lazy"`。
「渲染阻塞」被修掉之后要重新看 LCP 元素是谁；首屏图片不能懒加载。修法是前 8 张卡片
eager、第一张 `fetchpriority="high"`。教训：一次只改一个性能变量，改完立刻复测。

### 中文页的网络字体按「页面上的字」收费
同一份主页，英文版 LCP 1.0s、简体版 11.1s（PageSpeed 移动端）：Google Fonts 按字重 × unicode-range
切片下发 Noto Sans SC，中文页拉了 21 个文件 / 1.1 MB（外加 451 KB 的 CSS），在模拟慢速链路上
把首屏头像饿住了。只把样式表降成低优先级（`media="print"`）**没用**——Lighthouse 的模拟把
LCP 之前开始的请求都算进关键路径，字节不减就没救。根治是 `text=`：主页文字是固定的，
`tools/hub_fonts.py` 把每个主页**实际渲染的全部字符**（含拉丁字母——body 首选 Noto，漏掉拉丁会
悄悄换字体；含全部 ASCII——搜索计数是运行时写的）写进请求，四个字重保留，字体 1.1 MB→0.3 MB、
CSS 451 KB→12 KB。门禁 `test_hub_font_subset_covers_every_rendered_character` 防止改了文案没更新子集。
子集之后简体主页 LCP 仍是 3.8s（英文 1.0s）：0.3 MB 字体仍在 LCP 之前开始下载，模拟器把它们都算进去。
第二步（2026-11-19）改为 `load` 事件后再插入样式表（`<script id="hub-fonts">` + `<noscript>`），
慢速 4G 实测 CLS 仍为 0——字体晚到只换字形，不挪版面。但只等 `load` 时 PageSpeed 呈**双峰**（77/100/81：LCP 要么 1.1s 要么 5~6s）——
首张头像在节流 CPU 下有时在 `load` **之后**才绘制，那时字体已在途。现在等首张头像 `decode()`
再过两帧才请求字体，保证「有头像的那一帧」先于第一个字体字节。**PageSpeed 单跑不可信，
改动前后各跑三次再下结论**；本地可用 http.server + CDP 节流对拍「LCP 时刻 vs 首个字体请求」。注意：`apply_hub_fonts` 必须**先**匹配新的
loader 块，旧的 `<link>` 正则会匹配到 `<noscript>` 里的链接，导致每跑一次嵌套一层。
另：fonts.googleapis.com 在中国大陆不可达——以前那个阻塞式样式表会让大陆用户白屏到超时，
所以字体链接**永远不能阻塞渲染**。

### 设备相关的样式只给对应设备
触控目标 24px 的修复放在 `@media (pointer: coarse)` 里——桌面标题带的密度是设计定稿，
不能为了手机把它撑高。门禁的桌面/响应式几何状态因此不受影响。

### 写回文件时别改换行符（又踩了一次）
管线页的简体 HTML 是 **CRLF**。Python `open()` 读入时把 CRLF 折成 LF，以 LF 换行
写回就把整页换成了 LF——描述那次提交因此把 5 个管线页变成整页 diff（`8001fbe` 修过
同一件事）。`.gitattributes` 是 `* -text`，git 不会替你兜底。改这些页面要么走
`patch_legacy_pages.py`（它保留原换行），要么用 `newline=""` 读写；提交前用
`git diff --stat` 看行数是否和改动量相称。

### 门禁只看它被告知要看的那一类页面（2026-11-19 次日巡检）
发布后跑了一遍「全站静态扫描 + 多宽度浏览器扫描」，四个问题全都落在门禁的盲区里：
- **简体主页没有 hreflang**：交叉链接测试只 glob `*_tk8_movelist.html`，主页从来不在
  范围内。另两个主页指向它，它却不回指——Bing 只读 HTML 里的 hreflang。修法是
  `hub_i18n.with_alternates()` 重建（而非追加），派生主页继承后逐字节不变。
- **洛在平板宽度截断招式名**：684 状态只测固定几个宽度，管线页又不在几何门禁里。
  700–820px 下 19 个四字名显示成「龙构…」。**不要全局放开换行**——试过并实测：
  自动布局表里 `nowrap` 才是把名字列撑开的东西，一放开约 300 个名字被挤成两三行
  （龙/尾/扫）。只给唯一的固定布局表（`.synced-lists .movelist`）放开，
  恰好只有那 19 个换行。**改 CSS 前后各量一次逐格行数，比看一张截图可靠。**
- **管线页页脚对比度 2.7~3.9**、深色 `.tag` 2.2、两处 `opacity` 把 4.5 打下去：
  Lighthouse 只测默认（深色）主题，浅色主题从来没人量过。`<main>` 地标同理。
- **英文管线页丢了 78/79 个招式徽标**（热能发动/愤怒技/架势…）：英文构建整格替换
  招式名时把 `<span class="tag">` 一起扔了。现在走 `legacy_en.TAG_NAMES`（缺词即构建
  失败），测试要求英文徽标与简体逐页相等。
**教训**：门禁绿不代表没问题，只代表「门禁看的那些」没问题。每次大改后值得用
不同的切法（全部页面 × 多宽度 × 两主题）扫一遍。

### 共享 CSS 的注释不再进页面
共享样式表把设计理由写在注释里（这是对的），但它们被内联进每个角色页：44 KB 的
样式里注释占 19 KB，gzip 后整页 29→21 KB。`tools/css_inline.py` 在内联时剥掉
`/* */`（规则、空白、顺序不动；开闭标记数不等就拒绝，防止误伤字符串里的 `/*`）。
生成器的 PAGE_CSS 与记法组件、管线页注入的 `legacy-chrome` 块都走它；管线页自己
手写的样式不动。**注释照常写在源文件里**，页面上看不到是预期行为。

## 8. 主页动效事故与重设计的教训(2026-07-22 flux v3)

背景:主页背景特效经历 v1 漫游光环 → v2 色团呼吸 → v3 电脉·框流 三代,
前两代均"实现正确、QA 全绿、用户看不见/不满意"。完整决策史见
`design/specs/2026-07-22-homepage-circuit-pulse-design.md`(本地)。

### 感知与度量

- **"动画在跑"≠"人能看见"。** 人眼对缓变区域的觉察阈值约 8~10/通道且需在
  2~3s 内发生;软渐变纯平移的时域信号 = 空间梯度 × 速度,v2 实测 10s 仅
  ±2/通道——机制全对,信号量差一个数量级。**动效需求先估/测感知信号量再写代码。**
- **断言要对准用户可感知的结果**,不是 computed style。v2 的 15/15 断言全测
  "机制在跑"(animationName/playState),没有一条测"看得见"。现行做法:帧差
  探针(`workbench/qa/flux-perception.mjs`)把"肉眼可见"变成数字门禁。
- **振荡动画的三个度量陷阱**:① alternate+ease-in-out 在 phase 0 导数为零,
  开局最平(负 delay 让加载即处于陡坡区);② 固定偏移的 t0→tN 帧对比会碰上
  相位回归假阴性 → 必须多窗口采样;③ 事件式动效(雷击)单窗口必然抽风 →
  按"多数窗口有信号"断言。

### "渲染正常但看不见"的诊断分层

先分清三层,再动手改参数:**渲染冻结**(动画时钟停)/ **亚阈值**(在动但
信号量不够)/ **显示链路**(HDR/动态对比度压掉暗部)。一页阶梯诊断页
(高强度闪烁对照 + 目标参数 + 静止对照 + rAF FPS 计数 + 自动帧差数字)一次定位。
相关机制:Windows Chrome 有窗口遮挡检测,被完全遮挡/最小化的窗口其"活动标签页"
也会 document.hidden=true,且**隐藏标签页动画取样值冻结**——这是当时
"前台标签页却 hidden"矛盾数据的成因(实际上那个窗口不在屏幕上)。

### 与用户的迭代方法

- 用户说"看不见/太慢"时,把它当**测量结果**而不是口味分歧——先复现再谈参数。
- **原型演练场 + 按钮选档**(`workbench/qa/flux-ladder.html`)比文字描述收敛快
  一个数量级;强度/速度/质感类参数让用户在实物上选,不要替用户拍板。
- 用户需求是渐进披露的(本次:可见→高级感→编排感→气势→更自由→70% 匀速),
  小步快跑、每轮只改一件事;主观词要翻译成机制("廉价"=均匀亮段/硬直角/
  锯齿折线;"编排"=永不穿透+出口决定去向;"气势"=慢+长尾+大光晕,不是快)。

### 工程坑(主页特有)

- `body{zoom:1.25}` 下 getBoundingClientRect 返回视觉像素,JS 定位叠加层必须
  除以 `bcr.width/offsetWidth`。
- `.card{overflow:hidden}` 会裁剪辉光/外描边 → 特效放独立覆盖层(`.flxlayer`),
  不进卡片内部。
- offset-path 刚性拖尾在转弯处直切卡角;WAAPI 可直接动画已注册的
  `@property` 自定义属性(本页 `--flxa`),配 keyframes offset/easing 可做
  蓄力冲刺等韵律。
- 并发动效防穿透:按行分"领地带",数学上不相交,比碰撞检测简单且稳。
- 移除功能要连契约一起翻转:删 avatars-light 时把 assertIn 翻成 assertNotIn,
  否则死重会被悄悄加回来。

## 9. 角色页返回导航的教训(2026-07-24 方案 1a + 2b)

### 两条实测才敢下结论的事

- **`zoom:1.25` 下的 `position:fixed` 是安全的**。担心固定元素按 zoom 放大成
  1.25 倍视口宽、触发 `documentOverflow` 断言——实测 Chrome 正确折算了固定定位的
  包含块:1480 与 390 两个宽度下 `barWidth === docClient`,零溢出。
  但这是**实测结论,不是推理结论**;动 fixed 元素时重跑探针,别凭记忆。
  (注意与第 8 节的坑区分:`getBoundingClientRect` 返回视觉像素这条仍然成立,
  所以**滚动阈值不要写像素常量**——用 `IntersectionObserver` 观察 `#top` 判定
  "已离开 banner",与 zoom 无关。)
- **`transform:translateY(-100%)` 藏不掉 Tab 焦点**。位移出视口的链接仍在 Tab 序里,
  键盘用户会把焦点丢到看不见的地方。必须同时切 `visibility`,并把它的过渡延迟到
  位移结束(`transition: transform .2s ease, visibility 0s linear .2s`),
  才能既退出 Tab 序又保留滑出动画。

### 两套页面共用前端资源的办法

生成器页与管线页的 CSS 变量命名不一致(前者 `--accent/--bg/--muted`,后者
`--jade/--acc`),且**管线页夜间模式是给 `body` 设 `color` 而不是改 `--ink`**——
直接 `color: var(--ink)` 在管线页夜间会得到浅色主题的墨色。

`back_nav.css` / `back_nav.js` 逐字共用于 41 页,做法是只依赖两家都成立的东西:

- 文字色用 `color: inherit`(继承 body,两家夜/日都对)
- 背景写死 `rgba(255,255,255,.92)` / `html.dark` 下 `rgba(14,17,22,.92)`
  ——恰好等于两家 `--bg` 的实值
- 强调色经 `--bn-accent` 中转,各自样式块赋值一次

**不要为图省事在补丁脚本里复制一份 CSS**:41 页的样式必须只有一份真值,否则必然漂移。

### 幂等补丁脚本的坑

`patch_legacy_back_nav.py` 用正则定位 banner `<header>`——law 页的攻略区**也有一个裸的
`<header>`**,靠"后面紧跟 `<h1>`"区分。但打完补丁后面包屑 `<div>` 挤到了 `<h1>` 前面,
第一版正则复跑即失配。**正则必须同时匹配补丁前与补丁后两种形态**,写完立刻复跑验证幂等,
别等门禁。`--check` 模式已接入 `validate_season2.ps1`,页面与共享资源脱节即失败。

## 10. 角色页头像改版的教训(2026-07-25 Claude Design 方案 A)

### 先算留白,再选方案

设计稿的 B「边栏」承诺「表格宽度不变、边栏只占版心之外的既有留白」。**实测发现留白根本不够**:
版心 `max-width:1120px` 经 `zoom:1.25` 实占 1400 设备 px,于是

| 视口 | 版心外留白(CSS px) | 222px 边栏 |
|------|-----|------|
| 1920 | 416 | ✅ |
| 1728 | 262 | ✅ |
| 1600 | 160 | ❌ |
| 1480 | 64  | ❌ |
| ≤1280| 0   | ❌ |

门禁最宽的 1480 就放不下——与第 8 节撤回「浮动返回坞」是同一个陷阱:
**`zoom:1.25` 让版心实占远大于 CSS 数字,任何"用边槽"的方案都要先量再画**。
最终选 A「铭牌」(头像编入标题带),版心与表格分毫不动。

### mix-blend-mode: lighten 只在深色背景上成立

头像是 512×512 **深底白描**,靠 `mix-blend-mode: lighten` 抠掉黑底。但 lighten 取较亮者,
**主题色一浅(熊猫 #e6e9ee、莉莉 #cdd6e0)头像就整个消失**。
解法:`.hero::before` 垫一块 `#0a0d11`、`opacity:.5`、**用同一组遮罩**淡出的深板。
深色主题色下它几乎不可见,浅色主题色下它就是让白描可读的唯一依靠。
垫板的渐变要比图片遮罩**更长**(34%/68% vs 72%/88%),否则浅色底下会看出一块панель硬边。

### 抓官方资料的两个坑

`tekken.com/fighters/{slug}` 是 Angular 预渲染,数据在 `innertext="值"` 里,可直接 curl。
但:
- **标签大小写不统一**:多数页写 `style:`,anna/lili 等写 `Style:`。且不能直接匹配
  `style:`——内联 CSS 里有上千个 `font-style:`。必须锚定 DOM:`>标签:<span innertext=`。
- **slug 不可想当然**:azucena 要 `azucena-milagros-ortiz-castillo`,而 lidia 是 `lidia`
  **不是** `lidia-sobieska`。两者都返回 HTTP 200,错的那个只是没有角色卡——
  **用 HTTP 状态码判断 slug 对错会误判**,要看有没有解析出字段。

### 纯中文契约要靠断言守,不能靠自觉

架势胶囊原本取分区名首词作代号(`CD (Breaking Step)` → `CD`),
但 `Mist Step`/`Wind God Step` 的首词是英文单词,于是「雾步 Mist」这种中英混排漏进了页面。
新断言(发布契约 + 浏览器门禁双查 `<dd>` 内不得出现 4 个以上连续拉丁字母)当场抓到。
**只保留 `^[A-Z0-9]{2,5}$` 形状的真代号。**

### 补丁脚本的正则必须匹配自己的输出

又踩一次(见第 9 节):`<h1>` 补丁后尾部多了 `<span class="hsub">`,
原正则要求 `</small></h1>` 紧邻,第二次跑直接抛错。
**写完补丁脚本立刻复跑一次验幂等**,别等门禁。

## 11. 图例按记法切换的教训(2026-07-25)

### 缺陷只活在门禁看不见的那 5 页

36 个生成器页早在标题带改版时就把图例拆成了「恒显的判定/发生行 + 每种记法一半」,
5 个管线页却仍是旧的单行「指令说明」——两种记法下都常驻,于是按键图模式下多出一整段
文字记法说明,文字模式下反而缺分组。**能活这么久是因为 360 状态 Playwright 门禁
只覆盖 36 个生成器页**;管线页只有 `--check` 这种静态比对,而这是纯渲染态缺陷。

教训:**共享 chrome 的每一项都要在两家页面上各验一次**。已补两道:
`test_site_publication.py` 的 41 页标记/规则断言,和 `validate_season2.mjs` 里
5 页 × 3 记法 = 15 状态的实测可见性检查。静态断言证明不了「哪一半真的被藏起来」。

### 改造前先看被覆盖掉的是不是手写内容

管线页的图例是**逐角色手写**的,尾巴上挂着各自的东西:凌晓雨的
`凤凰=凤凰架势(AOP)　背身=雨舞背身(BT)　催眠=催眠师(HYP)`、克莱夫/国光二世的
`qcf=下前1/4圈`·`~F=按住前`、洛的 `龙构=龙构架势(DSS)`。第一版改造用
`pipeline.CONFIG` 的 prefix 映射**推导**架势代号去替换,信息更少也更干——
是 Law 回归测试断言 `龙构=龙构架势(DSS)` 才把它拦下来。

这些内容没有任何快照能重新生成,只能原样搬,登记在 `LEGEND_EXTRA`。
**动一段"看起来是模板"的旧内容前,先 `git diff` 看它到底是不是模板。**
(回归测试断言具体字符串,在这里正是它该起的作用。)

### 两家的 CSS 变量不同名,也不同值

`--line` 在生成器页随主题切换,在管线页是写死的浅绿(夜间是直接覆盖 `.legend` 的
`border-color`,没动变量)。共享文件里直接写 `var(--line)` 会让夜间的分隔线过亮。
照 `--bn-accent` / `--hc-accent` 的老办法,经 `--lg-line` 中转,各家在 `.legend`
上绑一次。

另外注入顺序有坑:`<style id="legacy-chrome">` 在页面自带样式**之后**,而管线页自带
一条 `body.txt-mode .gfx-only{display:none}`(0,2,0)。共享文件里的
`.legend .lgsub`(0,2,0)同分且靠后会赢,按键图那一半就藏不住了——所以模式规则一律
写成 `body.txt-mode .legend .lgsub.gfx-only`(0,3,0)。

## 12. 白字压主题色的教训(2026-07-25)

### 报上来的是两个角色,量出来是全部 41 个

起因只是"熊猫、莉莉的 `h2` 白字压近白底"。真去逐色算 WCAG,**41 个主题色没有一个
让白字过 AA**:最好的铠甲王 3.24:1,最差的熊猫 1.22:1。差别只在"勉强能读"和
"完全看不见",而肉眼只会在后者报警。

**先量再修**。凭观感只会修掉 2 个,剩下 39 个继续挂着。

### 我的探针错了两次,都是"墨在哪一侧"没想清

1. 第一版按"最暗 2% = 文字"取墨——白字压彩底时文字是**最亮**的一簇,于是
   `lo` 和 `hi` 都取到背景,比值 1.00,74 个页面全报"完美"。
2. 改成"墨取计算样式、底取像素中位数"后,切换按钮组在浅色主题下报 1.17,夜间报 5.04。
   查计算样式发现两边**完全一致**——是我取"右三分之一"时,浅色下那块正好是
   **填充态的选中按钮**(白底深字),而我拿父元素的白色当墨。

教训:自动对比度测量,**必须逐元素确定"墨"和"底"分别是什么**,不能对一个容器
取统计量了事。凡是子元素自带背景(按钮、胶囊)或自带 `opacity` 的,都要单独测。
两次都是先怀疑页面、后怀疑工具,顺序反了——数字和肉眼打架时,先查工具。

### 修法:压深表面,别改文字颜色

三个选项里选了"把主题色朝自己的 ink 压深到白字过 AA":
- 改文字为深色 → 部分角色的 ink 对自己的 accent 也不够(铠甲王 3.19,比白字还差);
- 重挑 41 套配色 → 工作量大且丢掉角色识别度;
- 压深表面 → **仓库里早有先例**,5 个管线页的 `h2` 一直用深色底白字,好看且能读。

`band_color()` 逐角色取"仍过 AA 的最大主题色比例",所以深色角色几乎不变
(卡祖亚保留很多),近白角色让出大部分(熊猫 `#e6e9ee` → `#6d778a`)。
41 个落在 4.50~4.61,刚好过线且各自最大限度保留本色。

### opacity 会把对比度预算一次花光

`h2 .en` 的 `opacity:.75` 让 4.50 掉回 3.23——band 是按**不透明**白字标定的。
层级已经由字号(9 vs 13)、字重(400 vs 600)、字距三重表达,不需要再靠变淡。
**用透明度做视觉层级,等于拿可读性换**;凡是标定过对比度的表面,文字一律不透明。

### 门禁必须验证它会失败

新加的两道门禁(逐页 hex 断言 + 浏览器计算样式实测)加完后,把熊猫的 band 改回
原始浅色跑了一遍:Python 断言失败、浏览器门禁 10 个状态失败并报
`contrast: heading is 1.22:1`;管线页那条单独用洛验证过。
**没验证过会失败的门禁,和没有门禁一样。**

### 解析器的"script 假设"会精确地只坑一个语系

`parse_cmd` 找状态胶囊的办法是「取开头的 CJK 连续段」——写它的时候页面只有中文，
这条规则和「取开头的状态词」等价，所以看不出问题。加了英文页才暴露：拉丁标签没有
CJK 连续段，`Left_throw`、每一条 `BT.` / `H.` 指令都被判成杂散字母、**整格回退纯文字**。
英文页 1732/5946 格，中文页 10 格。

修法是让 tokenizer 自己认状态词（`stateword` / `orword`），但**只收非 CJK 的**——
中文词继续走老路，简繁两棵树因此逐字节不变，改动的风险被关在一个语系里。同理，
`(wall stun)` 这种括号旁注原来的判据是「含 CJK」，其实想说的是「含词」，改成
「含词」后中文行为不变、英文不再回退。

**中文靠"是中文"白拿的东西，换语系就要显式登记**：
- 别名里的引导词（`Left`/`Right`/`Back`）——中文开头 CJK 一律成胶囊，拉丁没有兜底。
- `,DVK.` → 标签后**没补空格**。中文在 script 边界自然断词，`DVK` 会和后面的 `F`
  黏成 `DVKF`。补空格对中文是 no-op（tokenizer 跳空白），逐字节验证过。
- cram 档位的 `2.0 × 胶囊数` 是按中文胶囊（2~3 个全角字）标定的。`BT` 比它窄、
  `Opponent wall-stunned` 是它的四倍，所以中文保留常数、拉丁按字数量（`capsule_weight`）。

门禁写成**三语回退格数相等**，不是阈值：那 10 格是六方阵上限的设计内回退，
三语本就该一致，相等比「英文 ≤ 某个数」更早发现问题。

### 相对链接在派生页里会静静地指错地方

派生的 `/en/index.html` 逐字继承了手写主页的 `href="jun_tk8_movelist.html"`，
于是解析成 `/en/jun_tk8_movelist.html`——那 5 个管线页只有简体，全是 404。
门禁没抓到，因为 `test_all_local_references_resolve_inside_docs` 只 glob
`docs/*.html`，压根没进另外两棵树。**为新目录树加内容时，先问一遍现有门禁的
遍历范围有没有跟着走。**

### "翻译覆盖率"要按可见文本量，不按表的数量

三语构建收尾时我以为语料都过了 `localized_vocabulary`，实际漏了两张小表——
它们都不在翻译主路径上：

- `COMBO_MARKER_LEGEND`（`W!=撞墙`）只有中文一列，繁體靠 `convertLiterals` 兜住，
  英文页于是原样印简体。
- `COMBO_STANCE_ALIASES`（eddy `MD→曼丁加`）在渲染连招时**直接并进 `stance_names`**，
  绕过了 `localized_vocabulary`，所以英文页和繁體页都吃到简体胶囊。

**教训**：绕过本地化入口的 `{**a, **b}` 合并是最隐蔽的漏点——它看起来只是补数据。
门禁改成扫可见文本：英文页只允许四个槽位出现中文（ZH 标招式名、副名、副标题、
语言按钮），其余算泄漏。这条一写就同时抓到了两处，而按"表都过了吗"自查两次都没抓到。

### 英文术语宁可去快照里找，也不要回译

标记码的展开（`WH!` = Wall Hazard）是 Wavu 用语，不是可以从中文推回去的东西。
把 `*_combos.json` 的 `raw` 段 grep 一遍，Wavu 自己在附近就写了：armor_king 的
`f+1+4 WH! … Wall Hazard Combo Here`、raven 的 "Wall splat with T!"、lee 的
`(BB!)` 与 "Heat Burst" 小节标题。`_MARKER_LEGEND_EN` 里**逐条记了出处**。
唯一存疑的是 `WB!`：armor_king 的模板行写 "Wall Blast"，而 reina 的路线、
kazuya 的 "Wall Break, both soft and hard" 和 `HWB!`(=Hard Wall Break) 都指向
"Wall break"——取了后者，存疑点写在注释里，不假装确定。

### 门禁里的「允许槽位」就是文案的藏身处

英文页的第一版门禁写的是「四个双语槽位以外不得有中文」，它**通过了**，而页面上
`Throws 投技`、每个 h1 下的 `风间仁`、页脚一整句中文全都在。规则本身没错——错在
它是按当时的实现反写的，于是把缺陷编码成了契约。

改成「**除语言控件外，英文页不得有任何中文**」以后，同一次运行抓出了五处。
凡是门禁里写着「以下情况除外」，都要能说出这个例外**为读者做了什么**；说不出来的
不是例外，是漏洞。

### 「可见文本」比想象的宽

第一版扫描只看标签之间的文字，于是漏了三整类：

- `<meta name="description">` / `og:*` / `twitter:*` / JSON-LD —— 进搜索结果和分享卡片；
- `alt` / `aria-label` / `title` —— 读屏就是这么念的；
- **内联脚本里的字符串字面量** —— `cnt.textContent = raw ? n + ' 名匹配' : …`，
  一输入搜索框中文就冒出来。

现在 `test_site_publication.reader_text()` 三类全收，只剔除 CSS/JS 注释
（共享样式表里 `/* 阿丽莎 · 樱粉 */` 和图例里被引用的中文键不是页面文案）。

### 「Wavu 没有的东西」也分能不能自己造

同一句「Wavu 没给」，两件事的答案相反：

- **英文招式名**：Wavu 未命名 1371 条。回译中文名会凭空造出一个名字再把它当来源，
  所以先是显示中文 + `ZH` 标。最后改为给**描述**（不是名字）并保留角标说明来源——
  措辞变了，「不假装有来源」这条没变。做法是分词合成 + 从快照挖 Wavu 自己的架势词
  （`PKB (Peekaboo)` → `窥视`=Peekaboo），不是逐条拍脑袋。
- **繁體管线页**：根本不需要「Wavu 有没有」——繁體是简体语料的转换，而那 5 页
  自己就是语料。卡了几轮才发现，是因为它们一直被归进「等迁移」那一类。
  **「这件事缺什么」要逐项问，不要按类别打包。**
